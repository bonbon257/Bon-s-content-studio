# 三列内容工作台改造设计

## 背景

当前内容生成流程会在主内容生成时同时生成聊天记录。用户通常会先根据生成内容二次修改正文，再需要基于修改后的正文生成聊天记录，因此提前生成聊天会浪费 token，也容易与最终正文不一致。

当前页面设计功能也存在实际效果不足的问题：页面主体和卡片中仍有大量写死颜色，导致用户调整背景色后没有明显变化。同时页面设计设置现在是即时保存，缺少明确的“保存设计”动作。

本次改造目标是把内容生成页变成更清晰的三列工作台：左侧输入，中间正文，右侧聊天记录。AI 内容检索只出现在内容生成页，不新增独立功能页。

## 范围

本次实现覆盖：

- 文章改写和话题创作结果页默认不生成聊天记录。
- 按文档生成继续默认不生成聊天记录。
- 用户确认或修改正文后，在右侧聊天栏手动点击生成聊天记录。
- 内容生成页新增“AI 内容检索”入口，用于背景 check、点子检索、风险提醒和补充表达。
- 大屏结果页改为三列：输入区、正文区、聊天区。
- 小屏自动降级为上下布局。
- 页面设计面板新增“预览效果”“保存设计”“取消”“恢复默认”。
- 主题变量真正覆盖页面背景、卡片底色、文字色、强调色和圆角。

不在本次实现：

- 不新增独立“AI 内容检索”功能页。
- 不做多端历史同步。
- 不接入真实网页搜索或外部浏览器搜索，AI 内容检索仍通过当前 LLM 根据已有知识、上下文和事实谨慎规则输出。

## 用户体验

### 三列布局

大屏内容生成页采用固定三列：

- 左列：原文/话题/文档输入，国家、平台、生成按钮。
- 中列：标题、正文、标签、润色、二次修改、AI 内容检索、保存历史。
- 右列：聊天记录。

三列各自内部滚动，减少用户在输出框中频繁上下滑动。右侧聊天栏在无聊天时显示空状态：“确认正文后生成聊天记录”。

小屏和手机端使用上下布局，顺序为输入区、正文区、聊天区，避免横向挤压。

### 聊天记录

主内容生成只返回标题、正文、标签和事实自检，`chat` 固定为空数组。聊天记录只通过单独按钮生成：

- “生成聊天记录”：使用当前标题、正文、国家、平台。
- “按当前正文重生成”：用户修改正文后可重新生成整份聊天。
- “重生成本行”：保留现有单行重写能力。

聊天生成必须读取最新的标题、正文和标签，而不是生成时的旧内容。

### AI 内容检索

只在内容生成页结果区显示，不出现在独立导航中。入口名称为“AI 内容检索 / 背景 Check”。

用户点击后打开小面板，默认带入当前标题、正文、国家和平台。用户可以输入问题，例如：

- 帮我 check 这个背景是否真实。
- 这个点子有没有文化差异依据。
- 这个角度会不会太硬广。
- 补充一个更真实的外国朋友视角。

输出结构：

- 背景判断
- 可用角度
- 风险提醒
- 可加入正文的句子

检索结果不自动改正文，用户可复制或手动整合，避免 AI 自动覆盖已编辑内容。

### 页面设计

页面设计面板改为“先预览，后保存”：

- 打开面板时复制一份临时设置。
- 修改颜色/字体/布局密度时立即预览，但不写入本地存储。
- 点击“保存设计”后写入 `localStorage`。
- 点击“取消”时恢复打开面板前的设置。
- 点击“恢复默认”只恢复临时预览，仍需保存才落地。

CSS 改造方向：

- `--app-bg` 控制页面背景。
- `--app-panel` 控制卡片、主框架、输入背景。
- `--app-ink` 控制主文字。
- `--app-accent` 控制按钮、选中态、重点状态。
- `--app-radius` 控制主要卡片圆角。
- 将原有写死的 `#d4e8e0`、`#faf7f2`、`#1a1a1a`、`#f0b8b8` 等关键颜色改为变量。

## 技术设计

### LLM 层

修改 `generateFromArticle`、`generateFromTopic`：

- prompt 明确要求 `chat: []`。
- 保留 `factChecks`。
- 主生成阶段不调用聊天模型。

保留并复用 `regenerateChat`：

- 作为所有生成页的聊天生成入口。
- 输入当前最新 `title`、`post`、`country`、`platform`、用户补充建议。

新增 `researchGeneratedContent`：

- 参数：`title`、`post`、`country`、`platform`、`question`。
- 返回结构化 JSON：`summary`、`angles`、`risks`、`insertableLines`。
- 使用已有事实谨慎规则，避免编造具体数据。

### 组件层

拆分结果工作台：

- `OutputResult` 负责中间正文区。
- `ChatResult` 支持空状态和手动生成按钮。
- 新增 `AiContentCheckPanel` 负责检索输入和输出。
- `DynamicCard` 或主工作区在结果阶段使用三列容器，而不是把聊天记录放在正文下方。

按文档生成页保留现有左右结构，但结果区也采用“正文 + 右侧聊天”的模式；聊天默认关闭。

### 样式层

新增或调整布局类：

- `.mac-workbench-three`：大屏三列 grid。
- `.mac-output-column`：中间结果列。
- `.mac-chat-column`：右侧聊天列，支持 sticky 或内部滚动。
- 小屏断点改为单列。

主题变量覆盖：

- 页面根容器、主 frame、侧栏、顶部 tab、按钮、卡片、输入框、结果卡、聊天表格。
- 保留必要的透明度和渐变，但底色来源必须从变量计算。

## 错误处理

- 聊天生成失败时只影响右侧聊天栏，不清空正文。
- AI 内容检索失败时只显示检索错误，不影响正文和聊天。
- 主题保存失败时提示用户“保存失败，请检查浏览器存储权限”，但预览仍可继续。
- 如果用户未生成正文就点击聊天生成，提示“请先生成或填写正文”。

## 验证

实现后运行：

- `npm run build`

手动验证：

- 文章改写生成后聊天为空。
- 修改正文后点击生成聊天，聊天基于最新正文。
- 话题创作同样延迟生成聊天。
- 按文档生成默认不生成聊天，勾选/点击后才生成。
- AI 内容检索只在内容生成页出现。
- 三列布局在桌面端生效，手机端不挤压。
- 页面设计修改背景色、卡片色、文字色后视觉明显变化。
- 未点击保存前刷新不保留；点击保存后刷新保留。
